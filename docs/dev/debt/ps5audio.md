# Technical Debt & Architecture: PS5 Audio Integration

## 1. Overview and Hardware Topology

The PlayStation 5 AMD Oberon APU (Zen 2 CPU + Cyan Skillfish GPU, PCI `1002:13fc`) possesses no onboard analog audio codec (such as Realtek ALC or Conexant DACs) on the console motherboard. There are no 3.5mm analog audio jacks or analog line-out interfaces on the chassis.

Consequently, all system sound must be transmitted through digital interfaces:
1. **Digital HDMI Audio**: Embedded in the TMDS/FRL stream over HDMI 2.1 to the television or AV receiver.
2. **USB Audio**: Plug-and-play USB DACs, USB headsets, or the Sony DualSense controller connected to the console's USB-A or USB-C ports.
3. **Virtual Audio Loopback**: Software-based HAL audio device (BlackHole) providing a monotonic CoreAudio clock when no physical audio output is active.

## 2. HDMI Audio Architecture (AppleGFXHDA & DCN 2.0.1)

### Silicon Audio Engine
On AMD RDNA silicon, HDMI digital audio packetization is handled directly by the display engine:
- The PS5 APU incorporates AMD DCN 2.0.1 (Display Core Next).
- Audio sample packets, clock regeneration packets (N/CTS values), and Audio InfoFrames are generated by the DCN audio sub-blocks (AZALIA / HDAudio host interface) and interleaved into the horizontal and vertical blanking intervals of the HDMI stream.
- In macOS Monterey, `AMDRadeonX6000Framebuffer.kext` initializes the DAL (Display Automation Layer) display pipelines, which interface with the DCN 2.0.1 audio endpoints.

### PCIe Topology
The APU exposes two distinct PCI functions on bus 0x20 (downstream of root port / bridge `00:08.1`):
- **Function 0 (`20:00.0`)**: Cyan Skillfish Graphics Controller (`1002:13fc`, PCI Class `0x030000`).
- **Function 1 (`20:00.1`)**: AMD High Definition Audio Controller (PCI Class `0x040300`).

In QEMU / VM passthrough environments, these functions are assigned to device 1:
- `PciRoot(0x0)/Pci(0x1,0x0)`: Graphics endpoint.
- `PciRoot(0x0)/Pci(0x1,0x1)`: Audio endpoint.

### Driver Architecture & AppleGFXHDA
Apple provides native display audio through `/System/Library/Extensions/AppleGFXHDA.kext`, which operates in tandem with `AppleHDA.kext` and `IOAudioFamily.kext`:
- `AppleGFXHDA` does not bind to arbitrary audio devices by PCI ID alone.
- It requires an explicit pairing property, `hda-gfx`, in the I/O Registry.
- For pairing to succeed, **both** the graphics controller (`IOPCIDevice` for `AMDRadeonX6000Framebuffer` / `AMDRadeonX6000`) and the audio controller (`IOPCIDevice` for the HDA endpoint) must publish the identical property:
  ```xml
  <key>hda-gfx</key>
  <string>onboard-1</string>
  ```
- If `hda-gfx` is absent from either device node, `AppleGFXHDA` fails to associate the audio stream with the display framebuffer, and HDMI output options will not appear in the Sound settings pane.

### Dual-Layer Injection Mechanism

To ensure bulletproof pairing in both bare-metal and virtualized environments, `hda-gfx = onboard-1` is injected at two levels:

1. **Bootloader Injection (OpenCore `DeviceProperties`)**:
   In `tools/make_baremetal_efi.py` and `opencore/config.plist`, `DeviceProperties -> Add` injects `hda-gfx = onboard-1` for:
   - Bare-metal endpoints:
     - `PciRoot(0x0)/Pci(0x8,0x1)/Pci(0x0,0x0)` (GPU)
     - `PciRoot(0x0)/Pci(0x8,0x1)/Pci(0x0,0x1)` (HDMI Audio)
   - Virtualized / QEMU endpoints:
     - `PciRoot(0x0)/Pci(0x1,0x0)` (GPU)
     - `PciRoot(0x0)/Pci(0x1,0x1)` (HDMI Audio)

2. **Kernel-Level Dynamic Injection (`PS5Cyan` Lilu Plugin)**:
   In `kexts/PS5Cyan/kern_start.cpp`, the routine `publishHdaGfx()` is invoked:
   - When `AMDRadeonX6000` (accelerator) loads.
   - When `AMDRadeonX6000Framebuffer` loads.
   - During accelerator hardware info initialization (`wrapAccelHwInfo`).
   The function matches `IOPCIDevice` instances in the I/O Registry:
   - For `1002:13fc` (the GPU provider PCI device), it publishes `hda-gfx = onboard-1`.
   - For AMD HD Audio controllers (`vendor-id 0x1002`, `class-code 0x0403xx`), it publishes `hda-gfx = onboard-1`.
   This ensures that even if OpenCore device tree injection is bypassed or altered, `PS5Cyan` guarantees that both endpoints carry the requisite property for `AppleGFXHDA`.

## 3. DualSense Controller USB Audio: Capabilities, Limitations & Reality

### Hardware Interface & Sony macOS Specifications
The Sony DualSense wireless controller (CFI-ZCT1W) connects via USB-C or USB-A to the PS5's external USB ports. According to Sony's official macOS compatibility documentation:
- **Built-in Speaker & Built-in Microphone**: **NOT supported on macOS**. Apple's native driver stack does not map or expose the internal speaker or internal beamforming microphone array.
- **3.5mm Headphone Jack**: Supported for 2-channel 48 kHz stereo audio output **strictly over a wired USB connection**. Connecting the controller wirelessly via Bluetooth does not support audio output or input on macOS.
- **Microphone via TRRS Jack**: Headset microphones connected to the 3.5mm jack have inconsistent vendor support under stock `AppleUSBAudio` and are considered unverified on this platform.

### Zero-Kext Integration Profile (Wired Headphone Jack Only)
- Under a wired USB connection, macOS attaches `com.apple.driver.AppleUSBAudio` to the controller's USB Audio Class interface.
- Output through the 3.5mm headphone jack operates as a basic stereo endpoint in **System Settings > Sound**.
- **Current Status**: While compliant with standard UAC on generic Mac hardware, audio output through the DualSense on the PS5's specific xHCI / bus 0x20 topology has not yet been physically verified and remains a bare-metal hardware testing milestone.

## 4. BlackHole Virtual Audio Loopback (Preventing CoreAudio Stalls)

### CoreAudio Master Clock Requirement
In macOS, the CoreAudio daemon (`coreaudiod`) and the media playback framework (`AVFoundation` / `VideoToolbox` / `WebKit`) enforce synchronous playback timing against an active audio device clock (the master hardware timebase):
- In systems where no audio output device is present or active, CoreAudio cannot derive a hardware sample clock (`AudioHardwareDevice` timebase sync).
- When a web browser (Safari, Chrome) or media application attempts HTML5 `<video>` or `<audio>` playback (e.g. YouTube, Vimeo, local QuickTime movies), playback threads block indefinitely waiting for audio sample clock ticks.
- This results in video buffers freezing on the first frame, spinning loading indicators, and potential `WindowServer` hangs or thread deadlocks.

### BlackHole Architecture
To prevent playback stalls in headless environments or when neither HDMI Audio nor USB Audio is connected:
- **BlackHole** (`BlackHole2ch` / `BlackHole16ch`) is installed as a user-space CoreAudio HAL plug-in in `/Library/Audio/Plug-Ins/HAL/BlackHole2ch.driver`.
- It registers an in-kernel/user-space virtual audio loopback engine that generates a steady, continuous 44.1 kHz / 48 kHz clock timebase with zero latency and zero CPU overhead.
- When configured as the default system output, CoreAudio threads advance seamlessly, allowing web browsers and media frameworks to decode and play video at full framerate without stalling.

## 5. Known Limitations & Technical Debt

1. **Multi-Channel LPCM & Bitstream**:
   - Current HDMI audio routing defaults to 2-channel stereo PCM (48 kHz, 16-bit / 24-bit).
   - Multi-channel surround (LPCM 5.1/7.1) and compressed bitstream pass-through (Dolby Digital, DTS, Dolby Atmos) require extended CEA-861 Audio InfoFrame descriptors in DAL, which are currently restricted to stereo modes.
2. **Bluetooth Audio**:
   - The PS5's proprietary internal Bluetooth controller is not initialized by macOS.
   - DualSense wireless audio over Bluetooth is unavailable unless an external macOS-compatible USB Bluetooth dongle (e.g. Broadcom BCM94360 or Intel AX200/AX210 with BlueToolFixup) is connected.
3. **HDMI Hot-Plug Audio Re-Enumeration**:
   - Disconnecting and reconnecting the HDMI cable while macOS is running may cause `AppleGFXHDA` to lose the audio stream clock until display sleep/wake or resolution toggle re-triggers the DCN audio sub-block.
